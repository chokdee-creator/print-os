# เลือกบัญชี LINE ผู้รับยอด

ใช้ได้ในหน้าร้านปริ้นอิมเมจและโชคดีการพิมพ์ เมื่อติ๊กงาน แถบด้านล่างจะมีช่อง **ผู้รับ LINE** ให้เลือกก่อนกด **ส่งยอดชำระ** หน้าสรุปยอดค้างของปริ้นอิมเมจมีช่องผู้รับสำหรับปุ่มส่งเช่นกัน

- บัญชีเดิมคือ วินDS ผู้รับ `owner` ระบบส่งไปที่รหัสใน Script Properties เดิม
- ปุ่ม **บัญชี LINE → โหลดบัญชีที่ยืนยันแล้ว** โหลดตัวเลือกผ่าน Google เจ้าของร้าน ค่าเริ่มต้นไม่ต้องกรอกรหัสหรือกุญแจ
- บัญชีใหม่ต้องเพิ่มเพื่อน OA `@644iislz` แล้วจับคู่ Messaging API user ID ที่อยู่ใน channel เดียวกัน ชื่ออย่างเดียวหรือ LINE ID ทั่วไปใช้แทนรหัสนี้ไม่ได้
- ในหน้าบัญชี LINE มีตัวเลือกขั้นสูงสำหรับผู้ดูแลที่มีรหัสแล้ว ระบบเรียก LINE Profile API ยืนยันรหัสและดึงชื่อจริงก่อนบันทึก บัญชีที่ตรวจไม่ได้จะไม่เพิ่มในตัวเลือก
- ใช้รหัสที่ได้จาก webhook ที่ตรวจลายเซ็นแล้ว หรือวิธีทางการที่ยืนยันตัวตนผู้รับเท่านั้น ห้ามนำรหัสจาก URL หน้าแชท LINE OA มาใช้แทน
- ฝั่งเว็บเก็บเพียงชื่อและรหัสอ้างอิงสุ่มของตัวเลือก รหัสผู้รับจริงและ token อยู่ฝั่งเซิร์ฟเวอร์ รายการที่เก็บในเบราว์เซอร์ไม่ให้สิทธิ์ส่งเองได้ เซิร์ฟเวอร์ตรวจรายการอีกครั้ง
- ผู้รับใหม่ยังไม่ถูกเพิ่มและไม่มีการส่งข้อความไปบัญชีใหม่ในการติดตั้งครั้งนี้ ผู้ใช้ระบุว่ายังไม่ได้เพิ่มเพื่อน OA
- การส่งครั้งนี้จะใช้ผู้รับที่เลือก และแสดงชื่อผู้รับเมื่อส่งสำเร็จ รอบส่งอัตโนมัติเดิมยังคงส่งเข้าบัญชีเดิม ไม่ใช้ค่าจากตัวเลือกนี้
- นำบัญชีเพิ่มเติมออกจากรายการได้โดยผู้ดูแล แต่ไม่ลบบัญชีเจ้าของเดิม

โค้ดเพิ่มคือ `line-recipients.gs` และ `line-recipients.js` ไฟล์ `.gs` ต้องรวมอยู่ใน `OutstandingReports.gs` ที่ติดตั้งจริงร่วมกับตัวคำนวณและโมดูลเดิม และอัปเดต deployment เวอร์ชันใหม่

ทดสอบด้วย `node tests/outstanding-reports.cjs` ครอบคลุมเลือกผู้รับจริงใน payload ปฏิเสธผู้รับไม่รู้จัก การไม่เปิดเผย user ID ในรายการ ตรวจโปรไฟล์ไม่ผ่าน/ผ่าน การเพิ่มซ้ำ และการนำออก
